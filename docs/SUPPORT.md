# Help and participation

air is an early **alpha, before beta**. For help getting a sound, start with the [first-session guide](user-guide/getting-started.md) or [troubleshooting](user-guide/faq.md).

## Report a problem or suggestion

Click the **ALPHA** badge in air to prepare a report. Describe what you expected, what happened and the steps to repeat it. Your email is optional. Review the report below the message before sharing it; you can turn off the extra details. Choose **Copy report** or **Save to Desktop**. Saving creates an `air-feedback-…txt` file on your Desktop; if saving fails, use Copy report instead.

Nothing is sent automatically. Choose **Open the feedback page**, paste your reviewed report into the [feedback form](https://air.planetary.music/feedback), then choose **Send report**. Opening the webpage does not submit your report. Keep the confirmation ID after sending. If air will not install or open, use the same form without an in-app report. Include the air download version, Windows and music-program versions, and any error message. If the page is temporarily unavailable, keep your report and contact the maintainer through the route listed on the download page.

Share only material you have permission to send. Remove private paths, account information and third-party audio. Do not send a complete private project when a short description or original sound/MIDI example will do. [Security reports go privately](../SECURITY.md).

## Participate

Try the [alpha tester guide](user-guide/testing.md) for a short first-session check. Testing and clearer instructions help even if you do not write code.

Once public, use repository issue templates for ordinary bugs and focused suggestions. Search existing issues first. Give package/Windows/host version, sample rate, buffer size and a short reproduction. A minimal original preset or MIDI example is usually better than a private project. Remove account data, private paths and third-party audio. [Security reports go privately](../SECURITY.md).

Small contributions include testing one host workflow, improving a guide, supplying an original preset, reproducing a bug, or sharing an original musical example with distribution permission. See [CONTRIBUTING](../CONTRIBUTING.md). Propose larger DSP/UI/rack work first to avoid spending time on changes the project cannot maintain.

The instrument is free. Ongoing development and new racks take substantial time and money. Optional support is available through [GitHub Sponsors for Ricardo](https://github.com/sponsors/KadoBOT) and [Buy Me a Coffee](https://buymeacoffee.com/planetary_records). Consult each funding page for its own terms; contributing is not required to use air. There are no promised release dates, recurring air deliverables or rack commissions here.

Using relevant [Planetary creator services](https://planetary.music/services), including mastering and lyrics tools when useful to your music, is another way to participate. Their availability, prices and [terms](https://planetary.music/legal/terms) belong to those services; they are not required to use the instrument. The website has its own [privacy policy](https://planetary.music/legal/privacy). Both legal pages were verified through web retrieval on 2026-10-25.

Reports/contributions are reviewed as time permits. No response deadline, release schedule, indefinite compatibility guarantee or promise to implement a suggestion is established.
